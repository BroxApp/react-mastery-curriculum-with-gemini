🎯 مینی‌پروژه متمرکز و سریع: useFetch Hook Library
ما این مینی‌پروژه را طوری طراحی می‌کنیم که دقیقاً قابلیت‌های یک کتابخانه واقعی مثل React Query یا Axios را شبیه‌سازی کند، در کمترین زمان ممکن، فقط با تمرکز روی منطق خالص کاستوم‌هوک.

📌 اهداف اصلی این پروژه (فقط منطق هوک):
پشتیبانی از AbortController (Clean-up): جلوگیری از Race Condition و لغو درخواست در صورت Unmount شدن کامپوننت یا تغییر سریع URL.
پشتیبانی از پارامترهای اختیاری (options): امکان ارسال متد، هدرها، یا body.
قابلیت refetch دستی.
📋 صورت مسئله و تسک‌ها (Requirements):
شما باید فایل هوک خود را بسازید و ۲ سناریوی ساده را در App.jsx پیاده کنید:

۱. پیاده‌سازی کاستوم هوک useFetch(url, options = {})
این هوک باید:

خروجی‌های استاندارد { data, loading, error, refetch } را برگرداند.
با استفاده از AbortController، هنگام تغییر url یا Unmount شدن کامپوننت، درخواست قبلی را Cancel کند.
خطاهای شبکه (HTTP errors مثل 404 یا 500) را تفکیک و مدیریت کند (با نادیده گرفتن AbortError).


۲. پیاده‌سازی تست عملکردی در UI (بسیار ساده و بدون استایل پیچیده)
برای اثبات عملکرد چندمنظوره بودن هوک، فقط دو دکمه و یک لیست ساده در App.jsx قرار می‌دهیم:

دکمه جابجایی بین دو منبع داده (تست لغو درخواست / Dynamic URL):

دکمه ۱: دریافت لیست کاربران (https://jsonplaceholder.typicode.com/users)
دکمه ۲: دریافت لیست پست‌ها (https://jsonplaceholder.typicode.com/posts?_limit=5)
هدف: اثبات اینکه با کلیک سریع بین این دو، هوک بدون باگ داده‌ها را جابجا کرده و درخواست قبلی را با AbortController کنسل می‌کند.
دکمه Refetch:

یک دکمه برای فراخوانی تابع refetch هوک، جهت تست به‌روزرسانی دستی اطلاعات.
🗂️ ساختار فایل‌ها (ساده و مینیمال):

Apply
3.2-Custom-Hooks/
└── useFetch-Library/
    ├── src/
    │   ├── hooks/
    │   │   └── useFetch.js       <-- هسته اصلی پروژه و کاستوم هوک
    │   ├── App.jsx               <-- کامپوننت تست دو دکمه و نمایش لیست
    │   └── main.jsx
🏁 الگوی گام‌به‌گام برای پیاده‌سازی سریع:
گام ۱: داخل پوشه 3.2-Custom-Hooks/، پوشه‌ی پروژه به نام useFetch-Library را باز کن یا در یکی از پروژه‌های تمرینی که ساختی فایل useFetch.js را در مسیر src/hooks/ ایجاد کن.
گام ۲: منطق useFetch را با پشتیبانی از AbortController بنویس.
گام ۳: آن را در App.jsx با دو اندپوینت مختلف تست کن.
