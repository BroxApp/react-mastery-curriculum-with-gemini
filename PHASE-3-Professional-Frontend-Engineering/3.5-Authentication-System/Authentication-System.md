🛡️ Phase 3.5: Authentication Systems (معماری احراز هویت در فرانت‌اند)
در برنامه‌های واقعی، احراز هویت (Authentication یا Auth) صرفاً یک فرم لاگین ساده نیست؛ بلکه یک معماری سراسری برای مدیریت وضعیت کاربر، نگهداری امن توکن، کنترل دسترسی به صفحات و همگام‌سازی ارتباط با سرور است.

در این فاز یاد می‌گیرید که چگونه یک سیستم احراز هویت ماژولار، استاندارد و آماده استفاده در محیط Production را در React بسازید.

۱. توکن JWT چیست و چگونه کار می‌کند؟ (JSON Web Token)
توکن JWT یک رشته رمزنگاری‌شده استاندارد است که هویت کاربر را تایید می‌کند. ساختار آن از ۳ بخش تشکیل شده است که با نقطه (.) از هم جدا می‌شوند:

Apply
Header.Payload.Signature
Header: شامل نوع توکن (JWT) و الگوریتم رمزنگاری (مثل HS256).
Payload: داده‌های عمومی و اطلاعات کاربر (مثل userId, role, email, exp که زمان انقضاست).
⚠️ نکته امنیتی: Payload رمزگذاری شده نیست، بلکه فقط Base64-Encoded است؛ یعنی هر کسی می‌تواند آن را Decode کند. بنابراین اطلاعات حساس مثل پسورد هرگز نباید در Payload باشد.

Signature: امضای دیجیتال که توسط سرور با یک کلید مخفی (Secret Key) تولید شده تا کلاینت نتواند محتوای توکن را جعل کند.
۲. چرخه کامل حیات لاگین (Authentication Flow)
یک چرخه احراز هویت مدرن در فرانت‌اند شامل مراحل زیر است:

Apply
[ کاربر فرم لاگین را پر می‌کند ]
│
▼
[ POST /auth/login با ایمیل و رمز ] ───(خطا)───► [ نمایش ارور به کاربر ]
│
▼ (موفقیت)
[ سرور JWT Token + اطلاعات کاربر را برمی‌گرداند ]
│
▼
[ ذخیره توکن (localStorage یا HttpOnly Cookie) + آپدیت State سراسری Auth ]
│
▼
[ هدایت کاربر (Redirect) به صفحه مقصد یا داشبورد ]
│
▼
[ ارسال توکن در Header تمام درخواست‌های بعدی: Authorization: Bearer <TOKEN> ]
۳. کجا توکن را ذخیره کنیم؟ (مباحث امنیتی Storage)
در فرانت‌اند دو رویکرد اصلی برای نگهداری توکن وجود دارد:

| روش ذخیره‌سازی | مزایا | معایب / آسیب‌پذیری | کاربرد متداول | | :--- | :--- | :--- | :--- | | localStorage / sessionStorage | پیاده‌سازی بسیار ساده در فرانت‌اند، دسترسی مستقیم با JS | در برابر حملات XSS (Cross-Site Scripting) آسیب‌پذیر است | مینی‌پروژه‌ها، SPAها و پروتوتایپ‌ها | | HttpOnly Cookies | جاوااسکریپت به آن دسترسی ندارد، کاملاً در برابر XSS امن است | نیازمند تنظیمات سمت سرور، نیازمند محافظت در برابر CSRF | پروژه‌های Enterprise و سطح تولید واقعی |

📌 استاندارد در پروژه‌های تمرینی و مصاحبه‌ها: برای تسلط بر مفاهیم فرانت‌اند، توکن را در localStorage ذخیره می‌کنیم و آن را در لایه State (Context API یا Zustand) سینک نگه می‌داریم.

۴. کامپوننت محافظت از مسیرها (ProtectedRoute)
یکی از مهم‌ترین ارکان معماری Auth، جلوگیری از ورود کاربران ناشناس به صفحات خصوصی (Private/Protected) است.

الگوی پیاده‌سازی در React Router:
ما یک کامپوننت واسط به نام ProtectedRoute می‌سازیم که استیت احراز هویت را بررسی می‌کند:

اگر کاربر لاگین بود: محتوای صفحه خصوصی یا <Outlet /> را نشان می‌دهد.
اگر کاربر لاگین نبود: کاربر را با کامپوننت <Navigate to="/login" replace /> به صفحه ورود هدایت می‌کند.

Apply
// ساختار مفهومی ProtectedRoute
import { Navigate, Outlet } from 'react-router-dom';
import { useAuth } from '../context/AuthContext';

export function ProtectedRoute() {
const { user, isLoading } = useAuth();

if (isLoading) {
return <div>در حال بررسی وضعیت ورود...</div>;
}

return user ? <Outlet /> : <Navigate to="/login" replace />;
}
۵. ارسال توکن در درخواست‌ها (Authorization Header)
وقتی کاربر احراز هویت شد، برای تمام درخواست‌های محافظت‌شده به بک‌اند (مثل دریافت اطلاعات داشبورد یا سفارشات)، باید توکن را به هدر درخواست اضافه کنیم:

Apply
fetch('https://api.example.com/user/profile', {
headers: {
'Content-Type': 'application/json',
'Authorization': `Bearer ${token}` // استاندارد Bearer Token
}
})
